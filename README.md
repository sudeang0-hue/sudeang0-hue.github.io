## 페이지

- `dist/index.html`: 대표 영상·이미지와 세 분야 작업을 소개하는 시네마틱 홈
- `dist/development.html`: 기존 게임개발 소개와 대표 프로젝트
- `dist/gamelab.html`: Figma UI 흐름 설계, UI 리디자인, HUD 문제 해결, 결과 연출, AI 에이전트 활용·작업 자동화
- `dist/tasktown.html`: SceneFlow, Tutorial, 팀 기능 통합, AI 에이전트 활용
- `dist/resume.html`: 공통 이력서, 경력, 교육, 자격증, 연락처
- `dist/planning.html`: 굿즈 기획·제작 소개와 기획 → 제작 → 판매 → 돌아보기 사례 구성
- `dist/design.html`: 공공기관 홍보 작품과 공식 게시 기록 / 일러스트 작업 / 디자인 작업
- `dist/history.html`: 교육 및 자격·활동·근무 연혁

기존 공개 주소 `/`와 `index.html`은 새 홈으로 유지하며, 게임개발 목록은 `development.html`로 연결합니다. 기존 프로젝트·이력서·작품 상세 주소는 유지합니다. 상단의 홈·세 분야·연혁 메뉴는 모든 페이지에 공통으로 표시합니다. 게임개발의 전체 프로젝트·게임랩·TaskTown·이력서는 두 번째 메뉴에서 이동합니다. 게임랩과 TaskTown은 그 아래에 사례 목차를 고정하며, 클릭·스크롤에 맞춰 현재 항목을 색과 밑줄로 표시합니다. 소개 구간은 선택을 비우고 마지막 사례 이후에는 마지막 항목을 유지합니다. 굿즈 페이지의 고정 하위 메뉴는 답사·상품 기획 → 본인 일러스트 → 시안 협업 → 판매·발송 → 돌아보기 → 참가 활동으로 구성하며, 각 본문 영역으로 바로 이동합니다. 굿즈 하위 메뉴의 현재 항목은 클릭·스크롤에 맞춰 색과 밑줄로 표시됩니다. 굿즈 기획·제작 내용은 `goods-content.json`, 디자인 및 홍보 내용은 `design-content.json`, 레이아웃은 `design.mjs`에서 수정합니다. 편집·집계 기준은 `DESIGN-EDITING.md`, 공식 게시 출처는 `DESIGN-SOURCES.md`를 참고합니다. 기존 주소 연결을 유지하도록 굿즈 페이지 파일명은 `planning.html`을 사용합니다.

굿즈 페이지는 라디오회관 현장 답사 → 상품 구성 → 본인 일러스트 → 팀원 시안 피드백 → 판매·발송 → 돌아보기로 구성합니다. 본인 원화, 팀원 SD 원화와 본인 피드백, 공동 진열의 기여를 구분합니다. 선택한 답사·작업·행사 사진은 대표 이미지와 기본 접힘 갤러리로 나누며, 구매 후 개별 반응을 전체 판매 성과로 확대하지 않습니다. 활동 연혁 3건에는 행사 사진과 상세 연결을 표시합니다. 자료 수정과 남은 확인 항목은 `GOODS-EDITING.md`를 참고합니다.

## 내용 수정

공통 메뉴와 개발 페이지의 문구·캡션은 `generate.mjs`, 새 홈의 내용은 `home.mjs`를 수정한 뒤 `node generate.mjs`를 실행합니다. 홈 전용 화면은 `dist/home.css`, 타이핑·배경 전환·작업 카드의 재생 동작은 `dist/home.js`에서 관리합니다. 생성된 HTML만 직접 수정하면 다음 생성 시 덮어쓰므로 원본도 함께 수정해야 합니다. Notion 내용은 자동 동기화되지 않습니다.

홈의 Selected Work는 760px 이하에서 화면 높이 55%의 고정 기준선을 지나는 카드 하나를 자동으로 확대·재생합니다. 바깥 카드의 크기는 유지하고 내부 화면만 확대해 스크롤 위치가 흔들리지 않도록 합니다. PC는 기존 마우스 호버·키보드 선택을 유지하며, 모션 감소·데이터 절약 설정과 페이지 이탈 시 재생 중지를 적용합니다. `node check_home_interactions.mjs`로 스크롤 선택·이미지 전환·PC 입력·페이지 복귀 동작을 검사합니다.

게임개발 소개는 PC에서 상단 두 문구를 같은 높이에 두고 제목을 설명 영역의 세로 중앙에 배치합니다. 모바일은 상단 문구만 나란히 두고 제목과 본문을 세로로 표시합니다. `dist/development.css`와 `dist/development.js`는 이 페이지에만 적용하며, 대표 프로젝트는 PC 호버·키보드 선택 또는 모바일 고정 기준선에서 확대·영상 재생합니다. 선택 해제 시 기존 섬네일로 돌아오며 영상은 처음 위치로 정지합니다. `node check_development.mjs`로 영상 전환·썸네일 복귀·모바일 선택·페이지 상태를 확인합니다.

메이플스토리 비유는 게임개발 페이지의 소개에 한 번 사용합니다. 웹 이력서는 담당 경험을 요약한 별도 소개를 사용해 페이지 이동 시 반복을 줄였습니다. 게임개발 카테고리에서는 ‘게임 개발자’ 소개와 프로젝트별 실제 담당 역할을 유지합니다. 모든 분야에 공통으로 표시하는 브랜드는 `PORTFOLIO`, 하단 소개는 `최희수 · Portfolio`, 연락 문구는 ‘함께 만들 게임의 이야기를 기다립니다.’를 사용합니다.

이미지·영상은 `dist/assets/`에서 관리합니다. 파일 이름을 바꾸면 `generate.mjs`의 연결도 수정하고, 이미지 가로·세로 크기는 `asset-sizes.json`에 반영합니다. 디자인은 `dist/styles.css`, 이미지 확대·이메일 복사 등 동작은 `dist/app.js`에서 수정합니다.

게임개발 페이지의 대표 프로젝트 커버는 `gamelab-portfolio-cover-wide-v2.png`, `tasktown-portfolio-cover-wide-v2.png`를 사용합니다. 노션에 적용한 1600×690 이미지와 같으며, 카드도 같은 비율로 표시해 문구가 잘리지 않습니다. 커버를 교체할 때에는 이미지 안의 제목·역할 문구와 `generate.mjs`의 대체 텍스트도 함께 확인합니다. 프로젝트 상세 페이지의 실제 플레이 화면은 별도 이미지로 유지합니다.

게임개발 카드의 기간·팀 규모와 담당 역할은 `work-meta` 안의 두 줄로 나눕니다. 모바일에서도 13px을 유지합니다. 게임랩 비교 이미지의 `visual-notes`, TaskTown 구조도의 `diagram-intent`는 이미지에서 볼 지점과 목적을 설명하는 실제 텍스트이며 원본 이미지에는 합치지 않습니다.

모바일의 게임개발·프로젝트 소개, 카드·사례 설명, 이력서 본문은 14px을 기준으로 표시합니다. 인쇄용 글자 크기와 이미지 캡션은 별도로 유지합니다.

## 화면 모드

상단의 달 / 해 아이콘 버튼으로 다크 모드와 라이트 모드를 전환합니다. 화면에는 아이콘만 표시하고, 도움말과 스크린 리더에는 전환할 모드 이름을 안내합니다. 첫 방문은 기기 설정과 관계없이 라이트 모드입니다. 직접 선택하면 같은 브라우저의 페이지 이동과 재방문에도 선택을 유지합니다. 저장이 제한된 브라우저에서도 현재 페이지에서는 전환할 수 있습니다. 인쇄 / PDF 저장에는 밝은 색상을 사용합니다.

초기 모드 적용과 선택 저장은 `dist/theme.js`, 모드별 색상과 버튼 배치는 `dist/styles.css`, 공통 버튼 표시는 `generate.mjs`에서 관리합니다. 게임 이미지·영상·구조도의 원본 색상은 유지합니다.

## 상점 링크 추가·변경

`project-links.json`의 `gamelab` 또는 `tasktown` 아래 `steam`, `stove`에 해당 게임의 HTTPS 상점 주소를 입력한 뒤 `node generate.mjs`를 실행하고 새 버전을 공개합니다. 빈 문자열 `""`은 ‘준비 중’으로 표시되며 클릭되지 않습니다. 주소를 채우면 같은 위치가 자동으로 실제 링크로 바뀝니다. TaskTown의 기존 주소는 미리 연결되어 있습니다.

예: 게임랩 Steam 주소가 준비되면 `gamelab.steam`의 `""` 안에 주소만 넣습니다. Notion·GitHub 링크와 서비스별 아이콘은 공통 링크 표시에서 관리합니다. 아이콘 원본과 출처는 `dist/assets/icons/`, `ICON-SOURCES.md`에 있습니다.

## 확인과 공개

1. `node generate.mjs`로 페이지를 생성합니다.
2. `node check_home.mjs`로 홈의 4개 챕터·이미지 2초 전환·챕터별 10초 구성과 미디어·상세 경로를 확인합니다. `node check_security.mjs`, `python check_site.py`, `python check_security.py`로 HTML 입력 경계·내부 연결·제목·대체 텍스트·공통 보안 정책을 검사합니다.
3. `node preview.mjs`로 로컬 미리보기를 실행합니다. PC·모바일에서 정렬, 이미지 확대, 영상 재생을 확인합니다.
4. GitHub의 이 저장소 `main`에 올리면 GitHub Actions가 페이지를 생성·검사한 뒤 GitHub Pages에 자동 배포합니다. PR에서는 검사만 수행하고 배포하지 않습니다. 배포 상태는 저장소의 Actions에서 확인합니다.

배포에 필요한 소스 커밋은 사용자에게 변경 파일과 커밋 메시지를 보여주고 승인받은 뒤 진행합니다. 배포 인증 정보는 파일에 저장하지 않습니다.

## 검색 노출

HTML에 `noindex,nofollow`를 적용합니다. 검색엔진이 이 설정을 읽을 수 있도록 HTML 크롤링은 허용하고 `robots.txt`에서 `/assets/`만 차단합니다. 검색 제외 요청은 접근 제한이 아닙니다. 공개 사이트는 링크를 가진 사람이 열람·공유할 수 있습니다.

## 원본과 공개 범위

정적 배포 폴더는 `dist`입니다. 작업용 Notion 사본, 원본 파일 경로, 검토 스크린샷과 개인 백업은 배포 소스에 포함하지 않습니다. 사이트에는 이메일과 GitHub 연락처를 표시하며 전화번호·생년월일은 표시하지 않습니다.

공개 저장소에서는 소스와 이전 커밋 기록도 열람할 수 있습니다. 사이트의 검색 제외 요청은 GitHub 저장소 자체의 검색 노출까지 막지 않습니다. 업로드 전에는 연락처·파일·커밋 작성자 정보를 함께 확인합니다. 배포에는 GitHub가 실행 중 제공하는 임시 권한만 사용하며 별도 토큰을 저장하지 않습니다.

## 연혁 수정

교육 및 자격·활동·근무는 `history-content.json`에서 관리합니다. `HISTORY-EDITING.md`에 항목 추가와 날짜·역할·설명 입력 방법을 정리했습니다. 큰 화면에서는 두 항목, 모바일에서는 한 항목을 표시합니다. 교육 및 자격 → 활동 → 근무 순서로 좌우 드래그·터치로 순환하며, 선택 버튼은 상단에 고정되며, 누르면 해당 항목이 왼쪽에 배치됩니다. 아래에서 항목을 바꾸면 새 항목의 처음을 보여줍니다. 자격증은 취득 월·자격명·등급·발급기관을 표시합니다. 기간이 확인되지 않은 온리전 등 활동은 날짜를 만들어 넣지 않고 입력할 자리를 유지합니다.

## Figma UI 흐름 설계

게임랩 01절은 사용자 제공 연결 캔버스와 로비·전투의 초기 프로토타입을 보여줍니다. 페이지가 열리면 로비 흐름의 Figma 임베드를 자동으로 준비하며, 전투 흐름으로 전환하거나 선택한 흐름을 처음부터 볼 수 있습니다. 동작은 `dist/figma-prototype.js`, 배치는 `#flow` CSS, 문구·시작점은 `generate.mjs`에서 수정합니다. 기존 사례 앵커는 유지하고 번호만 한 칸씩 조정합니다. 자세한 출처·공유 범위·검수 방법은 `GAMELAB-EDITING.md`를 참고합니다.

## 게임랩 전후 비교 순환

전후 비교는 PC 두 화면·모바일 한 화면으로 표시하며, 마지막 다음에 첫 로비 화면이 이어집니다. 사진별 캡션은 비교 영역에서 제거하고 화면별 설명은 Before/After 아래에 모았습니다. 화살표와 제목을 함께 배치하고 화면 높이에 맞춰 사진을 조정합니다. 이미지 원본·대체 텍스트·확대 보기와 JSON의 기록용 캡션은 보존합니다. 편집 위치와 동작 검수 항목은 [GAMELAB-EDITING.md](GAMELAB-EDITING.md)를 참고합니다.

비교 페이지 번호는 왼쪽 사진을 기준으로 1~5를 표시합니다. 끝과 처음 사이도 한 장 이동한 뒤 동일 화면 위치로 정렬해 연속으로 이어지며, 빠른 입력과 모바일·모션 감소 설정을 함께 처리합니다.

굿즈 대표·답사 사진도 앞뒤 복사본을 이용해 양방향 경계를 같은 속도로 연결합니다. 대표 사진은 이동 완료 후 2초 표시하고 자동으로 넘기며, 답사는 수동 전환을 유지합니다. 사진·캡션·기여 구분은 보존하고 연타·폭 변경·모션 감소·확대창 일시정지를 함께 처리합니다. 자세한 편집 위치는 [GOODS-EDITING.md](GOODS-EDITING.md)를 참고합니다.
